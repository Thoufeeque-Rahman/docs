നിങ്ങളുടെ ഫെസ്റ്റിവലിലെ പ്രോഗ്രാം ഷെഡ്യൂളുകൾ, മത്സരാർത്ഥികളുടെ വിവരങ്ങൾ, ടീം പോയിന്റുകൾ, പബ്ലിഷ് ചെയ്ത റിസൾട്ടുകൾ, വാർത്തകൾ, ഫോട്ടോ ഗ്യാലറി എന്നിവ നിങ്ങളുടെ സ്വന്തം വെബ്സൈറ്റുകളിലോ മൊബൈൽ ആപ്പുകളിലോ സ്റ്റേജ് എൽ.ഇ.ഡി ഡിസ്പ്ലേകളിലോ തത്സമയം കാണിക്കുന്നതിനായി Festie ഒരു പബ്ലിക് REST API (`/public-api/v1`) നൽകുന്നുണ്ട്.

## Base URL

ഡെവലപ്പർമാർക്കുള്ള എല്ലാ പബ്ലിക് API അഭ്യർത്ഥനകളും (requests) HTTPS വഴി താഴെ പറയുന്ന അഡ്രസ്സിലാണ് ലഭിക്കുന്നത്:

```bash
https://api.festie.app/public-api/v1
```

നിങ്ങൾ സ്വന്തം ഡൊമൈൻ അല്ലെങ്കിൽ self-hosted സെർവറാണ് ഉപയോഗിക്കുന്നതെങ്കിൽ അതിനനുസരിച്ചുള്ള API ഡൊമൈൻ നൽകുക.

## പ്രധാന വിവരങ്ങൾ

<CardGroup cols={2}>
  <Card title="API Key Authentication" icon="key">
    എല്ലാ API കോളുകളിലും `X-API-Key` എന്ന HTTP request header വഴി API കീ അയക്കണം.
  </Card>
  <Card title="Server-Side Calls Only" icon="server">
    API കോളുകൾ നിങ്ങളുടെ സ്വന്തം backend സെർവറിൽ നിന്ന് മാത്രമേ ചെയ്യാൻ പാടുള്ളൂ. ബ്രൗസർ HTML-ൽ നിന്നോ ക്ലയന്റ് സൈഡ് കോഡിൽ നിന്നോ നേരിട്ട് വിളിക്കാൻ പാടില്ല.
  </Card>
  <Card title="SubFest Scoping" icon="layer-group">
    ഒരു ഫെസ്റ്റിവലിനുള്ളിൽ ഒന്നിൽ കൂടുതൽ sub-festivals (ഉദാ: ആർട്സ്, സ്പോർട്സ്) ഉണ്ടാകാം. `subFestId` അല്ലെങ്കിൽ `subFestSlug` വഴി ആവശ്യമായ സബ് ഫെസ്റ്റിവൽ തിരഞ്ഞെടുക്കാം.
  </Card>
  <Card title="Pagination & Limits" icon="list">
    ലിസ്റ്റുകൾ ലഭിക്കുന്നതിന് `page`, `limit` എന്നിവ ഉപയോഗിക്കാം. ഒരു പേജിൽ പരമാവധി `20` വിവരങ്ങൾ മാത്രമേ ലഭിക്കൂ.
  </Card>
</CardGroup>

<Warning>
  **പ്രധാന സുരക്ഷാ നിർദ്ദേശം: Server-Side Calls മാത്രം അനുവദനീയം**

  നിങ്ങളുടെ frontend ബ്രൗസർ കോഡിൽ നിന്നോ, വെബ്‌പേജിലെ `.html` ഫയലിൽ നിന്നോ, `<script>` ടാഗിൽ നിന്നോ നേരിട്ട് Festie API വിളിക്കാൻ **അനുവാദമില്ല**.

  - ബ്രൗസർ കോഡിലോ HTML-ലോ നിങ്ങളുടെ രഹസ്യ `X-API-Key` നൽകിയാൽ ആർക്കും Inspect Element വഴി അത് കാണാനും ദുരുപയോഗം ചെയ്യാനും സാധിക്കും.
  - നിങ്ങളുടെ ഫെസ്റ്റിവലിന്റെ പ്രതിദിന, പ്രതിമാസ API ക്വാട്ടകൾ മറ്റുള്ളവർ തീർക്കാൻ ഇത് കാരണമാകും.
  - അതിനാൽ നിങ്ങളുടെ സ്വന്തം Backend സെർവർ (Node.js, Next.js API Routes, Python, PHP, Go മുതലായവ) വഴി മാത്രമേ Festie API വിളിക്കാവൂ. അവിടെനിന്ന് ഡാറ്റ എടുത്ത് സുരക്ഷിതമായി നിങ്ങളുടെ വെബ്സൈറ്റിലേക്കോ ആപ്പിലേക്കോ നൽകുക.
</Warning>

## പെട്ടെന്ന് സെറ്റപ്പ് ചെയ്യാനുള്ള വഴി

<Steps>
  <Step title="API ഫീച്ചർ ഉണ്ടെന്ന് ഉറപ്പാക്കുക">
    Festie അഡ്മിൻ പാനലിൽ ലോഗിൻ ചെയ്ത് `Festival > Settings > API Keys` പേജിൽ പോവുക. നിങ്ങളുടെ സബ്സ്ക്രിപ്ഷൻ പ്ലാനിൽ Developer API ഉണ്ടെന്ന് ഉറപ്പാക്കുക.
  </Step>
  <Step title="API Key ഉണ്ടാക്കുക">
    **Create API Key** ക്ലിക്ക് ചെയ്ത് ഒരു പേര് നൽകുക (ഉദാ: `My-College-Website` അല്ലെങ്കിൽ `Stage-LED-Server`). ക്രിയേറ്റ് ചെയ്യുമ്പോൾ കാണിക്കുന്ന കീ സുരക്ഷിതമായി കോപ്പി ചെയ്തു വെക്കുക.
  </Step>
  <Step title="സെർവർ Environment-ൽ സേവ് ചെയ്യുക">
    നിങ്ങളുടെ backend സെർവറിലെ environment variable-ലേക്ക് (`.env`) ഈ കീ ചേർക്കുക. ഇത് ഒരിക്കലും GitHub-ലോ പബ്ലിക് കോഡിലോ നൽകരുത്.
  </Step>
  <Step title="സെർവറിൽ നിന്ന് API കോൾ ചെയ്യുക">
    Header-ൽ `X-API-Key` ചേർത്ത് ആവശ്യമുള്ള എൻഡ്പോയിന്റുകളിലേക്ക് റിക്വസ്റ്റ് അയക്കുക.
  </Step>
</Steps>

## SubFest സ്കോപ്പിംഗ്

ഫെസ്റ്റിവൽ വിവരങ്ങൾ മൊത്തത്തിൽ കാണുന്നതിന് പുറമെ, മത്സരങ്ങൾ, കാറ്റഗറികൾ, ടീമുകൾ, റിസൾട്ടുകൾ എന്നിവ ഒരു പ്രത്യേക സബ് ഫെസ്റ്റിനെ അടിസ്ഥാനമാക്കിയാണ് ഉണ്ടാവുക. ഇതിനായി റിക്വസ്റ്റിൽ താഴെ പറയുന്ന രീതിയിൽ സബ് ഫെസ്റ്റ് നൽകാം:

- **Query Parameter:** `subFestId=<uuid>` അല്ലെങ്കിൽ `subFestSlug=<slug>` ആയി നൽകാം.

```bash
curl -X GET "https://api.festie.app/public-api/v1/teams?subFestSlug=arts-2026" \
  -H "X-API-Key: YOUR_API_KEY"
```

## Pagination

ലിസ്റ്റുകൾ തിരിച്ചു നൽകുന്ന എല്ലാ API-കളിലും താഴെ പറയുന്ന പരാമീറ്ററുകൾ ഉപയോഗിക്കാം:

| Parameter | Type | Default | വിവരണം |
| :--- | :--- | :--- | :--- |
| `page` | `integer` | `1` | ഏത് പേജിലെ വിവരങ്ങളാണ് വേണ്ടത്. |
| `limit` | `integer` | `20` | ഒരു പേജിൽ പരമാവധി എത്ര എണ്ണം വേണം (പരമാവധി `20`). |
| `sortBy` | `string` | varies | ഏത് ഫീൽഡ് പ്രകാരമാണ് സോർട്ട് ചെയ്യേണ്ടത് (ഉദാ: `name`, `displayOrder`). |
| `sortOrder` | `string` | `ASC` | `ASC` (ആരോഹണ ക്രമം) അല്ലെങ്കിൽ `DESC` (അവരോഹണ ക്രമം). |

## HTTP Status Codes

Festie Public API നൽകുന്ന പ്രധാന സ്റ്റാറ്റസ് കോഡുകൾ:

| Code | Status | അർത്ഥം |
| :--- | :--- | :--- |
| `200` | OK | റിക്വസ്റ്റ് വിജയകരമായി പൂർത്തിയായി ഡാറ്റ ലഭിച്ചു. |
| `400` | Bad Request | ആവശ്യമായ പരാമീറ്ററുകൾ (ഉദാ: `subFestId`) നൽകിയിട്ടില്ല അല്ലെങ്കിൽ തെറ്റായ ഫോർമാറ്റിലാണ്. |
| `401` | Unauthorized | `X-API-Key` നൽകിയിട്ടില്ല, അല്ലെങ്കിൽ നൽകിയ കീ തെറ്റാണ്/കാലഹരണപ്പെട്ടു. |
| `403` | Forbidden | സബ്സ്ക്രിപ്ഷനിൽ ഈ ഫീച്ചർ ലഭ്യമല്ല അല്ലെങ്കിൽ ക്വാട്ട കഴിഞ്ഞു. |
| `404` | Not Found | തിരഞ്ഞ ഐറ്റം സിസ്റ്റത്തിൽ കണ്ടെത്താനായില്ല. |
| `429` | Too Many Requests | ഒരു മിനിറ്റിൽ അനുവദിച്ചതിൽ കൂടുതൽ റിക്വസ്റ്റുകൾ അയച്ചു (Rate limit). |
| `503` | Service Unavailable | ക്വാട്ട സർവീസ് താൽക്കാലികമായി ലഭ്യമല്ല. |
